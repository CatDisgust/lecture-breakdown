# 课件知识点拆分

复习策略分三步：① 用这个 skill 把每节课快速过一遍，理解重要知识点 → ② 做一遍样卷，弄清考什么 → ③ 根据样卷做专项练习。这个 skill 只负责第 ① 步。出整套题、押题不在这里做，只给出“考法预判”，留给第 ② 步验证。

## 讲解原则（每一步都要遵守）

1. **先讲场景，再给符号**。很多人看到一串公式符号会卡住，但给一个具体算例马上就能算。讲公式时，先用一个真实场景把问题讲清楚，再引出公式；公式里每个符号都要对应回“它在场景里是什么”。一讲里符号多时，给一张「符号 ↔ 含义」对照表。
2. **能画图就画图**。流程、状态变化、组件之间谁调用谁、两种方案的对比，都主动画图，不要等用户要求。对比两个概念时，图上要让两者的区别一眼可见；两张图看起来差不多，就说明没画对。默认用缩进树或文字框图，在终端里也能看；界面能渲染 Mermaid、SVG 或有画图工具时，用更清楚的方式画。
3. **新词第一次出现就解释，不用没解释过的缩写**。缩写第一次出现时写全称并说明意思。不要用一个新术语去解释另一个术语。
4. **从用户已经会的东西接上**。用户提过自己的背景（比如学过的课、会的编程语言和框架）时，讲新概念先对应到这些熟悉的东西，再回到课件。没提过就不要假设。
5. **给具体内容，不要只说“对应什么”**。说“这和第 2 周的 X 有关”时，要把 X 的具体内容拿出来讲，不能只报名字。
6. **一个点讲通了再往下**。自测没答、或者答得不对，就不要进入下一个知识点。
7. **纠错要直接**。答错时，直接指出错在哪一句、正确的说法是什么，不要先夸再绕。

## 讲解方式：按 Aha 的方法讲

每个知识点的讲解都按 [Aha](https://github.com/CatDisgust/aha-skill) 的方法来（环境里装了 aha skill 时，直接按它的说明讲）：

- 从用户已经懂的地方接上，不重讲他会的部分。
- 用一个具体例子把中间每一步、每个状态的变化走完，不只给开头和结果。
- 需要时打类比：从熟悉的东西讲起，对应回真正的概念，并说明类比在哪里不成立。
- 点出最常见的错误理解。
- 最后用一两句话说清核心关系。

## 输入

- 一份或几份课件：PDF、PPTX 或截图。一次处理一讲（一个 lecture / 一周）。
- 可选：课程代码、考试形式（闭卷 / 开卷 / 限制开卷）、已经卡住的地方。

没给考试形式时，先问一句；用户不知道就按闭卷处理。同一门课问过一次就记住，不要每讲都问。

## 第 1 步：读完整份课件

- 每一页都要读，包括图、表、公式和讲者备注。读取方式按环境来：有处理 PDF / PPTX 的 skill 就用它；没有的话直接读文件，或用命令行工具提取文字（如 `pdftotext -layout`、`python-pptx`）。
- 先提取全部文字，再把文字很少、主要是图的页面单独渲染成图片看，不能只读提取出来的文字。实在看不到图时，要告诉用户哪几页没看到，不要凭页面标题猜内容。
- 页码用课件上印的页码。PDF 页码和课件页码对不上时（比如缺页），以课件页码为准，并说明一句。
- 跳过纯行政页（课程安排、作业截止日期、致谢等），但如果有“考试会考 / important / key takeaway”之类的提示，要记下来。

## 第 2 步：拆知识点

**粒度**：一个知识点 = 一个能被单独考到的概念、机制、方法或公式。一讲通常拆成 6–15 个。

- 例子、动机页、过渡页并入它们所服务的知识点，不单独成点。
- 同一个概念分散在几页的，合并成一个点，标出全部页码。
- 一个点如果需要三段以上才能讲清楚，就拆成两个。

**重要度**，三档：

| 档位 | 判断信号 |
|---|---|
| 核心 | 讲者花了多页；有公式、算法步骤或完整例题；出现在总结页；被标为 key / important；和作业、样卷直接相关 |
| 重要 | 支撑核心点的概念；有对比表或定义框 |
| 了解 | 背景、历史、扩展阅读、一笔带过的内容 |

每个点给出判断依据（例如：“p.12–15 共 4 页 + 总结页再次出现”），不要凭感觉打分。

**排序**：按依赖关系排，先讲前置知识，不按页码顺序。几个点构成一条因果链时（比如 并发 → 饱和 → 瓶颈 → 排队），在知识地图里点出来，建议连着学。

## 第 3 步：先给一张知识地图

```
## Lecture X：<主题>（共 N 个知识点）

| # | 知识点（English term） | 重要度 | 依据 | 依赖 | 页码 |
|---|---|---|---|---|---|
| 1 | ... | 核心 | ... | — | p.3–6 |
| 2 | ... | 重要 | ... | 1 | p.7 |

建议顺序：1 → 2 → 4 → 3 …
主线：<一句话说清这一讲的主线>
时间有限时，只学“核心”档。
```

知识点之间有分支或汇合关系时，加一张结构图。

## 第 4 步：逐个讲透

默认从第一个核心点开始；用户指定了起点，或者跳着学，就按用户说的来。每次讲一个点：

```
### <#>. <知识点>（<English term>）· <重要度> · p.<页码>

**一句话**：它是什么。
**解决什么问题**：没有它会怎样，为什么要发明它。
**怎么运作**：先讲场景和机制，再给公式；公式里每个符号对应回它的含义。需要时配图。
**例子**：用一个具体例子走完每一步。优先用课件里的；课件里没有，就自己编一个并标注（课件外补充）。
**易错点**：最容易混淆或误解的 1–2 处，以及和相邻概念的区别。
**考法预判**：最可能怎么考（定义 / 比较 / 计算 / 应用场景 / 画图），一行。
**自测**：一道小题，答案先不给。
```

讲完等用户答自测题：

- **答对**：用一句话确认，指出他答案里最关键的那一点，然后进入下一个知识点。
- **答错或说不会**：判断卡在哪：前置概念缺失、两个概念混淆，还是机制没想通。只补卡住的那一环，不要整段重讲；第一次没讲通，第二次换一个例子或者画图，不要用同样的话再说一遍。补完换个角度再问一次。
- 追问最多两轮。两轮之后还没通，就直接把答案讲清楚，把这一点记入“卡点记录”，然后问用户是否继续。

**两种省时间的模式**：

- 用户说“**只讲理解**”：从这个点开始不出自测，每个点照常讲完整，讲完一个直接进入下一个。
- 用户说“**快速过**”：只讲核心点，不出自测，最后统一出 3–5 道自测题。

## 第 5 步：本讲收尾

讲完或用户喊停时，输出：

1. **已掌握**：自测通过的知识点；只讲了理解、没做自测的点单独列出来。
2. **卡点记录**：没通的点，具体卡在哪一环，以及最后讲通用的是哪个例子或哪张图。没答的验证题也列在这里。
3. **留给样卷验证**：各个“考法预判”汇总成勾选清单，第 ② 步做样卷时逐条核对。
4. **按考试形式补一项**：
   - **开卷 / 限制开卷**：A4 笔记候选条目。只收翻书也想不起来的内容（公式、步骤、对比表、符号表），每条一行。
   - **闭卷**：必背清单（定义、公式、算法步骤），每条一行，方便默写。

然后直接把这一讲整理成一份笔记，不用等用户开口：平台支持创建文档时就建一份文档，否则在对话里输出一份完整的 Markdown 笔记。笔记包括：知识地图、每个知识点的要点和讲解时用到的图、卡点记录、考法清单，以及 A4 候选条目或必背清单。

## 规则

- **只以课件为准**。课件外的补充解释、例子要标注（课件外补充）；和课件说法冲突时，以课件为准并指出差异。
- **术语保留英文**：考试是英文的。中文讲解，关键术语第一次出现时写成“中文（English）”，之后可以只写英文。
- **讲解不是翻译**：不要逐页复述课件。每个点都要回答“为什么”和“怎么运作”。
- **简短**：每个知识点的讲解控制在一屏左右，图不算在内。用户想深入时再展开。
- **不出整套题**：样卷和专项练习是后两步的事，这里只给自测小题和考法预判。
